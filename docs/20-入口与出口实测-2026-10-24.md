## 三、为什么现在几乎找不到"入口 = 出口"

纯直连（订阅里的 IP 就是出口 IP）意味着：一个 IP 同时承担"被大量用户连接"和"访问境外目标"，特征极明显，几天内就会被封。

所以行业标准做法是**分离**：

| 角色 | 通常选什么 | 特点 |
|---|---|---|
| 入口 | 大厂云（AWS/腾讯云/Google/Microsoft/Cloudflare）+ 中转 | 带宽大、抗打、IP 便宜、封了能换 |
| 出口 | 小 ISP / 落地机房 / 家宽 | 干净、原生 IP、能解锁流媒体 |

本次样本里入口全是 AWS / 腾讯云 / Google / Microsoft，出口全是 Linode、Eons Data、中华电信、香港本地小机房 —— 完全符合这个分工。

---

## 四、对监控这件事的含义

1. **订阅只能告诉你"入口还在不在"**，不能告诉你"出口还行不行"。出口换了、落地被封了，订阅可能毫无变化。
2. **节点名不可信**：`🇭🇰 香港01` 的入口可能在台湾（ayucloud 那条：入口 114.42.192.93，中华电信 HiNet，TW）。要看位置就看 IP 归属。
3. **入口 IP 的归属不代表落地归属**：bygcloud 入口是腾讯云，出口在香港；判"这条线路在哪个国家"必须看出口。
4. 想监测出口，必须**真的连上去**（本仓库 `airmon/probe.py` 目前只做 TCP 握手，连不进协议层，所以测不到出口）。

## 五、自己怎么验（不需要信我）

```bash
# 1. 把节点导入你的客户端，选中它
# 2. 查"我是谁"
curl -s https://ipinfo.io/json          # 或 http://ip-api.com/json/
# 3. 对比
#    返回的 ip == 节点表里的"解析 IP"  → 直连型
#    返回的 ip 是另一个              → 中转型，这个新 IP 才是出口
```

再查这个出口 IP 的归属：`https://rdap.org/ip/<出口IP>`，看 netname/org 是哪家。

## 六、本次实测的方法与踩坑

工具链（一次性脚本，未入库，在 `.tmp_ver/`）：

| 步骤 | 做法 |
|---|---|
| 挑样本 | 全库扫节点，筛 `直连 / 专线 / 普通地区名` 三类，每机场取一个，做 TCP 握手，留下能连的 |
| 起代理 | WSL `Ubuntu-22.04` 里的 `mihomo v1.19.29`，单节点配置，`mixed-port` 独立端口 |
| 查出口 | `curl -x http://127.0.0.1:<port> http://ip-api.com/json/` |

四个坑（都在脚本注释里写了）：

1. **`mode: global` 会静默走 DIRECT** —— 用 global 时 mihomo 走 GLOBAL 组而不是你写的 `MATCH,G` 规则，实测查出来是本机 IP（223.74.115.38 中国移动），看起来像"节点没生效"。必须 `mode: rule` + `rules: [MATCH,G]`。
2. **ipinfo.io 免费额度会被限流**（返回 429 "Rate limit hit"）—— 主源换 `ip-api.com`（http、无限流），备源 `cloudflare.com/cdn-cgi/trace`。
3. **mihomo 必须由调用方前台持有** —— `nohup ... &` 放在 `wsl bash -c` 里，wsl 一退出进程就没了，日志和端口都空。
4. **hysteria2（UDP/QUIC）在 WSL NAT 下连不通** —— maxiong 那批"直连-V305/V206/V223"全是 hysteria2，TCP 能握手但 QUIC 出不去，所以这轮没能测到它们。要测需要 Windows 原生 mihomo。

另外 `reality-opts`（public-key / short-id）和 `ws-opts`（path / Host）不写进配置，vless/vmess 一律握手失败 —— bygcloud 和 selom 都是 REALITY。
