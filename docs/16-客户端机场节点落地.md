## 2. 三条取数路线的实测结论（这是本轮最重要的方法学输出）

### 2.1 路线 A：客户端落盘配置 —— 全部加密，走不通

| 客户端 | 关键文件 | 实测 |
|--------|----------|------|
| SpeedCat / wandacloud / FastLink / hhy / QingyunLite / 0dcloud | `config.yaml`、`profiles/999999.yaml`、`profiles/*.dat` | 头部 magic 非 gzip/zstd（`0f61170b`、`64356870`、`082708141b`、`0d01ae56`），`grep '^  - name:'` 命中 0 → Flutter 侧加密存储 |
| DOVE | `config.xml` / `config2.xml` | `<tokenconfig><token1..8>` base64 密文；`cache.db` 非 sqlite（`file is not a database`） |
| SSRDOG | `isar/default.isar`（1 MB） | 无 `http`/`subscribe`/`vless://`/`ss://` 明文；密钥在 `flutter_secure_storage_windows_plugin` |
| QQT | `nfx-rt/rd.bin` 17.4 MB、`rs.bin` 10.6 MB | ENCv3 密文；`transactional-egress-selected-node-v1.json` 只有 sha256 |
| LetsPRO | `Lets-Data.db3` | 表只有 `MessageCenter`/`ImageCache`/`FreezeRedirectCache`，**无节点表** |

`python -X utf8 run.py scan-win-client --airport <slug> --dir <AppData目录>` 对 10 台逐一跑过，**10 台全部 `[提示] <slug>: 未直接获取到节点`**。

### 2.2 路线 B：从本机 SQLite 挖订阅 URL —— 6 台挖到（本轮最大意外收获）

`%APPDATA%\<pkg>\<pkg>\database.sqlite` 表 `profiles` 是 FlClash 系的订阅索引，**未加密**：

| 机场 | 订阅 URL（token 已截断保护，完整值见 `data/client_nodes/` 与快照 meta） | 抓取结果 |
|------|---------------------------------------------------------------------------|----------|
| speedcat | `https://scesa.web.ak005.com/api/v1/client/subscribe?token=＜已隐藏＞` | **403** nginx |
| fastlink | `https://flesa.apiv2.a047.com/api/v1/client/subscribe?token=＜已隐藏＞` | **403** nginx |
| qingyunti | `https://qytesa.apiv2.a047.com/api/v1/client/subscribe?token=＜已隐藏＞` | **403** nginx |
| wandacloud | `https://521wdy.xiongmao139.cn/cgi-bin/get/api/domain/ip/access?token=＜已隐藏＞` | 200，但 `proxies` 只有 2 条占位 |
| hhy | `https://gogogo.vo0.site/api/v1/client/subscribe?token=＜已隐藏＞` | 200，但 `proxies` 只有 2 条占位 |
| lingdian | 无（`profiles` 表 0 行，只有 `profiles/340519010418298880.dat`） | — |

- **403 不是 UA/token 问题**：换 10 种 UA（clash.meta / FlClash / Clash / v2rayN / Shadowrocket / okhttp / Dart / ClashX…）、加 `&flag=clash`、走代理与直连，结果一致；连这三个 host 的根路径 `/` 也 403 → **服务端 IP 级封禁**。
- **200-占位**是机场侧的"客户端禁用"提示：`proxies: [{name: 套餐到期：长期有效, type: ss, server: 127.0.0.1, port: 1}, {name: '⚠️ 当前客户端已被禁用 ⚠️', …}]`。wandacloud 内存里 6 条同款占位（`⚠️请登录官网获取客户端`/`⚠️www.z1z1.top`/`⚠️遇到问题请联系客服`）→ 与订阅一致，是**账号/客户端状态**问题，不是抓取技术问题。

### 2.3 路线 C：从 core 进程内存抽"运行期配置" —— 成功，且拿到完整字段

FlClash 系客户端把**合并后的运行期配置**交给 core，配置文本常驻 core 内存：

- `SpeedCatCore.exe` / `wandacloudCore.exe`：**JSON** 片段，例：
  ```json
  {"flow":"xtls-rprx-vision","name":"香港-01","network":"tcp","port":10201,
   "server":"scapp-xxxx.llguanglisf.com","servername":"dll4zb61k5i5hqdmop…",
   "skip-cert-verify":true,"tls":true,"type":"vless","udp":true,
   "uuid":"fc74efdc-5afe-3294-92b2-9e8562b07d40"}
  ```
- `FastLinkCore.exe` / `hhycenterCore.exe`：**YAML** 文本，例：
  ```yaml
  proxies:
    - flow: "xtls-rprx-vision"
      name: "🇭🇰-01"
      network: "tcp"
      port: 10101
      server: "abtappfb-1hiqvz8sd.mv4qz.llguanglisf.com"
      servername: "18d6f076ufole8mprr0jsyk9z3sg5v4i8rt"
      skip-cert-verify: true
      tls: true
      type: "vless"
      udp: true
      uuid: "de4e1722-ef11-39d9-96c2-a94db29e448d"
  ```
  → 有 `type`/`uuid`/`servername`（=SNI）/`flow`/`tls`，**直接就是可用的 mihomo 代理对象**。

**为什么旧的 `memory_scan` 拿不到**：`airmon/memsan.py:59 SEARCH_PATTERNS` 只认 JSON 风格 `"server":"…"`/`"port":`/`"password"` 与裸 `ip:port`，**不认** `server_port`、`"type"`、`"method"`、`"servername"`、YAML 形态；所以它只能给出 `server:port`，`protocol` 全 `unknown`。

**本轮脚本（都在 `.tmp_ver/`，可原样复用）**：

| 脚本 | 作用 |
|------|------|
| `dump_nodes_mem.py <pid> <slug>` | 抽 SSRDOG 那种 `[{"type":"anytls",…}]` 节点数组 |
| `dump_core_nodes.py <pid> <slug>` | **主力**：同时处理 JSON 对象与 YAML 文本两种落form，逐条抽取（容忍内存碎片/截断），输出 `{"proxies":[…]}` |
| `harvest2.py <slug…>` | 一键：启动客户端 → 等 core → 多轮抽取取最好结果 → 摄入 → 关客户端 |
| `ingest_any.py <slug> <file>` | `ingest-profile` 的通用版（支持只在 `credentials.yaml` 里的机场，见 §5.3） |
| `scan_yaml_mem.py` / `probe_nodeobj.py` / `dump_config_mem*.py` | 侦察用（标记计数、协议痕迹、整段配平）——保留作为排查工具 |

## 3. 每台的落地细节

### 3.1 ssrdog —— ✅ 36 个 AnyTLS
- 路径：`SSRDOG.exe`（PID 74020，Console 会话，**免提权可读**）内存里就有节点 JSON 数组（Flutter 侧下发结构，含 `type/server/server_port/password/sni`）。

### 3.2 speedcat —— ✅ 50 个 VLESS
- `SpeedCatCore.exe`（PID 48920，用户态）内存 JSON：`"proxies":[{…}]` 被分配器打断，整段 `json.loads` 失败（`Invalid control character at: line 1 column 3843`）→ 改**逐对象配平解析**成功。

### 3.3 fastlink —— ✅ 39 个 VLESS

## 5. 代码级优化建议（按性价比排序）

### 5.1 把"core 运行期配置抽取"做进产品代码（最高优先）
新增 `airmon/corecfg.py`，把 `.tmp_ver/dump_core_nodes.py` 的能力产品化：
- 输入 `pid`/`slug`，输出 `list[dict]`（已是 mihomo 代理对象），支持 JSON 对象与 YAML 文本两种落form、逐条容错、去重；
- `run.py scan-memory` 增加 `--core-config` 开关：先用 `memsan` 粗扫拿 `server:port`，再尝试配置抽取，**抽到就写完整节点**（本次实测 3/3 台 FlClash 系成功）。
- `airmon/memsan.py:59` 的 `SEARCH_PATTERNS` 应补 `"server_port"`/`"servername"`/`"sni"`/`"cipher"`/`"method"`/`"uuid"` 与 YAML 形态（`server:` 后跟端口块）。

### 5.2 快照覆盖策略：完整字段不能被"丢字段扫描"盖掉
实证事故：15:23 我摄入 ssrdog 36 个 AnyTLS 完整节点 → 15:30 `run.py all` 的 `scan-memory` 又写了一条 47 个 `unknown` 的快照，成为"最新"，`nodeset` 立刻变成 0 可导出。
建议 `airmon/store.py` 增加 `merge_latest`：新快照若**缺 `protocol`/`password`/`uuid`**，而最近一条同名机场快照有完整字段，则按 `server:port` 合并（保留完整字段），而不是简单覆盖；或在 `nodeset` 里改为"取最近一条**可导出**的快照"。

### 5.3 `ingest-profile`/`set-sub` 只认 `airports.yaml`（13 条）→ 45 条 credentials 机场全部不可用
`run.py:120 airport = get_airport(args.airport)` 走 `airmon/config.py:22`，只读 `airports.yaml`；`fastlink/hhy/qingyunti/dovex` 等只在 `credentials.yaml` 里 → `KeyError: 未知机场: fastlink`。
建议 `get_airport` 找不到时回落到 `credentials.yaml` 的 `accounts[slug]`（`name=slug`），这样 `ingest-profile`/`watch`/`pull`/`diff` 全线可用。

### 5.4 `nodeset` 默认写 `nodes/` 太危险
本次我误跑默认参数，把 `nodes/index.json` 覆盖成"1 台 / 0 节点"（已由主控修复）。建议：
- `--out` 默认改为 `nodes/` 但在写入前检测"本次导出台数 < 上次 index.json 台数的一半"时**拒绝写入**并提示 `--force`；
- 或默认写 `nodes/.staging/` 再原子替换，避免半成品覆盖整轮产物。

### 5.5 扫描要按"会话"分流，而不是按机场类型
同一台机器上：`SSRDOG.exe`/`SpeedCatCore.exe`/`FastLinkCore.exe`/`hhycenterCore.exe` 在 Console 会话 → 免提权可读；`0dcloudCore.exe`/`DOVE.exe`/`nanocore.exe` 在 Services 会话 → 必须提权。
建议在 `run.py` 里加 `--elevated-hint`：启动前用 `tasklist /FO CSV` 判断 core 的会话名，`Services` 就直接提示"需管理员"并打印确切命令，**不要**盲扫 60 秒再报 error 5。
