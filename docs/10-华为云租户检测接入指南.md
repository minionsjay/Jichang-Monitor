# 华为云租户「翻墙/机场」检测——接入指南

> 目标：在另一台电脑上拿到华为云日志，回本机用检测引擎出评分报告。
> 引擎：`airmon/huawei_detect.py`（判据来源 = WSL《华为云机场流量主动识别-方案总纲》§3 判据体系 + docs/07 离线验证）。
> 2026-10-19

---

## 一、总体架构

```
【采集端：能访问华为云的电脑】              【分析端：本机 Jichang-Monitor】
  华为云 LTS 日志服务                          机场基建关联库（自动加载）
   ├─ VPC 流日志（推荐，免费全量）              44+ 机场节点 IP/域名（最新快照）
   │    十分钟窗口聚合，无域名无 payload        + 域名全集 155 活域
   ├─ CFW 日志（可选，有 dst_host 域名）    →   python -m airmon.huawei_detect
   ├─ DNS 解析器日志（可选，QueryName）          ├─ 适配器：CSV/JSON → 统一会话
   └─ 导出 CSV / JSON（或 API 拉取）            ├─ 判据 J1-J6 评分卡
         ↓ 拷贝到本机                           └─ → data/huawei_findings.json
        data/huawei/<日期>.csv                      （面板后续接入）
```

**本机关联库就是最强判据**：日志里出现的目的 IP / 域名，只要命中本机 44 机场
的节点基建（2600+ 节点的 IP 与域名、155 个活域名），直接判「机场基建命中」。

## 二、采集端：开哪些日志、怎么导

### 2.1 开通优先级（按性价比）

| 优先 | 日志 | 为什么 | 成本 |
|---|---|---|---|
| ★★★ | **VPC 流日志** | 五元组+字节+时长全有，10 分钟聚合窗口；判据 J1-J5 全靠它 | 流日志免费，LTS 存储计费 |
| ★★ | CFW 日志（若已购） | 唯一有 `dst_host` 域名 + `app` 应用识别 | 按带宽规格计费 |
| ★ | DNS 解析器日志 | `QueryName` 域名；仅部分区域且只对内网解析器生效 | 按 LTS 计费 |
| — | HSS 主机指纹 | 端口 30 秒级，主机侧佐证 | 按 Host 计费 |

注意（官方限制，均已核实）：流日志单网卡每 10 分钟最多 40 万条（超出丢弃）；
仅部分 ECS 规格支持；中国站 NAT 网关无会话日志（走 NAT 出公网的流量必须
靠流日志/镜像，否则五元组不可得）。

### 2.2 操作路径（控制台）

1. **开通**：VPC 控制台 → 流日志 → 创建（粒度选 子网/VPC 最省事）→ 上报到 LTS
2. **查询**：LTS 控制台 → 日志管理 → 找到流日志的日志流 → 查询（跨度 ≤30 天/次）
3. **导出**：查询结果页「导出」按钮 → CSV（控制台单次 ≤250 条；**API 单次 5000 条**）
   - 数据量大：那台电脑装 KooCLI（hcloud）用 API 分页拉，或 LTS 转储 OBS 后整桶下载
4. **交付**：把导出的 CSV/JSON 拷到本机 `E:\Hermes-Agent\Jichang-Monitor\data\huawei\`

## 三、分析端：一条命令出报告

```bash
# 自动识别格式（vpc-flowlog / cfw-json / generic-csv）
python -m airmon.huawei_detect --in data/huawei/<日志文件>.csv

# 指定格式
python -m airmon.huawei_detect --in xxx.csv --fmt vpc-flowlog

# 不拿真日志先看效果（内置合成样本）
python -m airmon.huawei_detect --selftest
```

输出 `data/huawei_findings.json`（原子写；含 `scope=internal` 注记——
**报告含内部 IP，勿外传**）：

```json
{ "generated_at": "...", "input_sessions": 12345,
  "airport_lib": {"airports": 46, "ip_dom_entries": 2600, "domains": 155},
  "entities": [ { "dst": "1.2.3.4", "score": 100, "level": "strong",
                  "hits": ["applegame"],
                  "why": ["机场节点IP命中:applegame", "扇入3源", "长连接3条"],
                  "sample": [...] } ],
  "summary": {"entities_total": 1, "strong": 1, "mid": 0} }
```

## 四、判据与评分卡

| 判据 | 逻辑 | 分值 |
|---|---|---|
| J5 机场基建命中 | dst/src 命中本机机场节点 IP | **+90** |
| J6 机场域名命中 | dst_host/QueryName 命中域名全集活域 | +80 |
| J3 目的扇入 | 同一 dst:port 被 ≥3 个不同源连接（共享代理池） | +25（≥10 源 +35） |
| J2 高位端口 | dport≥10000 且占比 >50% | +20 |
| J1 长连接大流量 | duration≥600s 且 bytes≥10MB，每条 +10 | cap 30 |
| J4 字节比异常 | bytes/packets > 8000（少报文大流量=加密隧道） | +15 |

`level`：**strong ≥70** / mid 40-70 / low <40（low 不出报告）。
单一判据不强报（无基建关联时最高 25 分）——避免把正常大文件下载/视频会议
误伤；两条以上判据叠加才进「疑似」。

## 六、合规红线（总纲原文结论）

- 自采自用合法：分析的是**自己 VPC/账号内的日志**
- 不对第三方主动探测：不做端口扫描、指纹投递、主动发包
- 不训模型：判据全部是可解释规则；推理可用开源权重
- 报告含内部 IP：`scope=internal`，勿上传公网
