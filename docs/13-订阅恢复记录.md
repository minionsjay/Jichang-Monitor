## 7. 本轮新发现、要写进代码与监控的点

1. **采集器需要"按机场出网"能力**：kuainiao 面板在国内直连是 SNI 阻断（TCP 通、TLS 超时），DNS 还被污染到 `59.24.3.174`。现在 run.py 没有 per-airport 代理配置，这类家永远失败且会被误判成"链接失效"。本机 `127.0.0.1:10808`（v2rayN/xray）实测可用，可作为验证手段。**注意：订阅路径 `/api/v1/client/subscribe` 在代理出口被 Cloudflare「Attention Required」403，与 token 无关**——所以"经代理就一定能取"也不成立，需要区分"面板域/订阅域"分别取证。
2. **登录实现必须按面板分型**，现在混在一套 WHMCS 逻辑里：
   - v2board/Xboard：`GET /api/v1/guest/comm/config` → `POST /api/v1/passport/auth/login`（json）→ 拿 token → 订阅在 `/api/v1/client/subscribe?token=`
   - SSPanel/metron：`form#login_form` → `POST /auth/login`（form）→ 返回 `{"ret":0,...}` → 订阅在 `/link/<token>`
   - 自研 SPA（bywave）：`POST /api/v1/auth/login`（json + 可选 `captcha_token`）→ `Authorization: Bearer` → `GET /api/v1/subscriptions`
   docs/12 记录的 bywave「登录页未找到 CSRF token」正是"按 WHMCS 找、实际是 SPA"的误判。
3. **凭证类故障只能人工一次性处理**，脚本重放口令有锁号风险（R-26）。建议把"登录失败"从每轮日志噪音改成"告警 + 人工工单"，且**同一家失败后 N 轮内不再重试**。
4. **504 ≠ 链接失效**：lingdian 面板域 `/link/…`、订阅主机 `/link/…` 一致 504 —— 这是订阅后端整站故障，判据应是"多入口同码 → 机场侧故障"，这样 `stale_over_6h` 之类的告警才不会误导。
5. **面板换代要能识别**：bywave 从 WHMCS 变成自研 SPA，`u.bws.lol` 首屏还会白屏一次（需 reload）。健康检查应能区分"面板活着但登录方式变了"和"面板挂了"。
