## 3. DSH 插件体系勘察结论（只读研究，2026-10-18）

### 3.1 侧边栏面板的注册方式（问题①）

DSH Web UI 的侧边栏是 slot 驱动的。本 profile 已装官方层 `@deepseek-ai/dsh-web-app` 提供 `ui-sidebar`（左轨）等行；客户端插件经 `ctx.slots.inject(slotName, factory)` 向 slot 注入组件。**本 profile 内已验证的两个左侧栏先例**：

- **@local/eprint-workbench**（源码 `F:\DSH-Workspace\插件安装\eprint-workbench`）：左轨图标 + 主列面板双注册：
  ```js
  ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
    { name: 'sidebar.panellist', id: 'eprint', order: 20, label }, PanelIcon));   // 左轨图标
  ctx.slots.inject('main', () => ctx.slots.register(
    { name: 'main', key: 'eprint', locale: NS }, makeLauncher(ctx)));             // 主列面板
  ```
  sidebar 把 `panellist` 的 `id` 直接映射到同名 `main` panel 的 `key`，点击图标即 `ctx.layout.selectPanel('eprint')`。
- **@local/agent-bar**（源码 `F:\DSH-Workspace\插件安装\agent-bar`）：同样的左栏注册 + **沙箱 iframe 页面**模型（`sandbox="allow-scripts allow-forms allow-modals allow-popups allow-popups-to-escape-sandbox"`，页面数据经注入桥 `window.agb` 的 postMessage 转发）。其 examples 里就有「HTML 仪表盘装进侧栏面板」的成品实例（`install-eprint-page.mjs` + 34KB 仪表盘页）。
- **dsh-better-sidebar@0.28.0**（第三方工作台）：向所有插件开放 `ctx.betterSidebar.registerTab(TabDescriptor)` 等服务，生态 30+ tab 插件——若日后安装，可作为第二接入点（`available()` 特性检测后注册，见 §9）。

**结论**：注册一个左侧栏面板是一等公民能力，无需 fork 官方 UI，几十行 client 代码即可；且「静态 HTML 页面装进侧栏」在本 profile 有完整可抄先例（agent-bar）。

### 3.2 cordis.patch.yml / composition 加载机制（问题②）

- bundle 的 `package.json.dsh.bundle.patch` 指向一个 yml；加载器按 profile `dsh.profile.bundles` 顺序逐层合并。
- 方言要点（已核对 composition reference 与三个先例）：
  - `- insert:\n    - id: X\n      name: '@scope/x'`：向根列表**追加**一行，行 id=X、由包 `@scope/x` 提供。
  - 只写 `- id: X`（无 insert）：**覆盖**已存在行——config 整体替换、需重述全部字段；truthy `name` 断言原提供者；目标不存在则警告跳过。
  - 行字段：`id / name / config / disabled / inject / intercept / isolate`；`!!js` 表达式在注入激活后于插件 ctx 上求值；`group: true` + `name: cordis:group` 使 config 成为嵌套列表；`isolate` 映射服务名→realm。
- 本 profile 的 `cordis.patch.yml`（`C:\Users\minions\.dsh\profiles\desktop\`）即为 profile 级覆盖层实例（如 `- id: better-sidebar\n  name: dsh-better-sidebar\n  config: {...}`）。

### 3.3 插件 manifest 结构（问题③）

最小 Host-only 形（本方案的骨架即此形）：

```json
{
  "name": "@local/airmon-sidebar",
  "type": "module",
  "exports": { ".": "./index.js", "./client": "./client.js" },
  "engines": { "dsh": "*" },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web", "immediately": true, "inject": ["@deepseek-ai/dsh-client-ui-slots", "..."] }
  }
}
```

- Host 导出面：`export const name` + `export const inject = ['webServer', 'webRuntime']` + `export async function apply(ctx)`；资源经 `ctx.effect()` 注册并返回清理函数。
- 客户端导出：`./client` 文件内 `window.__ModuleLoader__.load({ id: 包名, factory(require){...} })`，factory 返回 `{ inject: ['slots','layout','locale'], apply(ctx){...} }`；React 从浏览器模块表 `require('react')`。
- 显示元数据：`locale/en.json` + `zh.json` 的 `meta.title / meta.description`；`icon` 经 exports `"./icon"`（或顶层 icon 字段），SVG ≤256KiB 且必须在包内；`exports` 需含 `./locale/*.json` 与 `./icon`；`files` 列全部运行文件（link 安装不经 files 过滤）。

### 3.4 最接近「侧边栏面板」的已装先例（问题④）

## 4. 技术选型对比（任务①之 A/B/C）

| | **A 纯静态 HTML iframe 面板**（寄生已装 agent-bar） | **B cordis 插件注册侧边栏面板**（自有 bundle） | **C 独立 Web 服务 + 链接** |
|---|---|---|---|
| 实现方式 | 把原型 HTML 经 agent-bar `POST /agent-bar/api {method:'page.set'}` 装成某智能体页面 | 自建 bundle：host 壳提供 `/airmon-sidebar/api/*`，client 注册左轨图标 + 沙箱 iframe 面板 | `python -m http.server` 托管 dashboard，DSH 里只放一个外链 |
| 独立入口/图标 | ❌ 寄生在 agent-bar 页面树，非独立左轨图标 | ✅ 左轨独立图标「机场监控」 | ❌ 只有书签/iframe 外链 |
| 数据新鲜度 | 装入时快照，更新需重新 POST | ✅ 打开面板即读最新 index.html（mtime 缓存） | ✅（服务活着才行） |
| 生命周期 | 随 agent-bar；卸载 agent-bar 即失效 | ✅ 随本插件独立启停/升级 | ❌ 需自管进程/开机自启/随机端口 |
| 安全面 | 沿用 agent-bar 栅栏 | ✅ 同源 + sec-fetch-site + loopback/trustedHosts 栅栏（照 eprint） | ❌ 额外本机端口暴露 dashboard 原始数据（含节点服务器域名/IP，**违背零机密交付意图**） |
| 是否改动现有代码 | 否 | 否（旁路消费 index.html） | 否 |
| 开发量 | 极小（1 个 POST 脚本） | 小（骨架已写好，§7） | 极小但不合格 |
| 长期可维护 | 差（借宿） | ✅ 好（自有版本、自有数据管道） | 差 |

**推荐：路线 B**，理由：
1. 用户诉求的落点是「**在 DSH 界面里随时点开**」——只有 B 提供一等公民的左轨入口与面板生命周期。
2. 数据面只有 B 能做到「打开即最新 + 强制白名单脱敏 + 不新增暴露面」：host 进程内读文件→过滤→同源返回，仪表盘原始机密字段（节点服务器域名/IP、面板地址）永远不出 host 进程。
3. 两个先例插件把每一层（manifest、patch、slots、栅栏、沙箱 iframe）都趟平了，风险低、骨架可直接落。
4. A 可作为**零安装的临时演示**手段保留（原型页本来就是静态的），C 直接排除（安全面 + 端口管理都不合格）。

**B 路线内部形态决策**：面板主体用**沙箱 iframe 加载插件托管的静态页**（agent-bar 模式），而非 React 原生渲染（eprint 模式）。理由：原型页即插件页（一套代码两处用）；UI 迭代不用碰 React 工具链；页面与桥协议同源自研，无第三方内容，风险等同 client.js。数据经 **postMessage 桥**由 parent（client）代取——沙箱 opaque origin 无法直接 fetch 同源接口，这正是 agent-bar 选桥的原因。

## 5. 推荐架构（路线 B 细化）

```
┌─ DSH Host (Node) ──────────────────────────────┐
│ @local/airmon-sidebar  index.js (host 壳)       │
│   ctx.webServer.register({kind:'prefix',        │
│     path:'/airmon-sidebar/api', handler})       │
│     ├─ GET /data   → logic.js: 读                │
│     │     E:\Hermes-Agent\Jichang-Monitor\      │
│     │     dashboard\index.html (mtime 缓存)      │
│     │     → 提取嵌入 JSON → 白名单过滤            │
│     │     → 读不到则回退包内 data.json 快照        │
│     ├─ GET /panel  → panel.html (原型页发布副本)  │
│     └─ GET /data.json → 构建时快照（兜底）        │
└──────────────┬─────────────────────────────────┘
               │ 同源（webServer 与 Web GUI 同 origin）
┌─ DSH Web GUI (浏览器) ─────────────────────────┐
│ client.js：                                     │
│   slots.inject('sidebar.panellist') → 左轨图标   │
│   slots.inject('main') → 面板 = 沙箱 iframe      │
│     src=/airmon-sidebar/api/panel               │
│   message 桥：iframe postMessage{airmon:get}    │
│     → parent fetch('/airmon-sidebar/api/data')  │
│     → postMessage{airmon:data, payload} 回 iframe│
└────────────────────────────────────────────────┘
```

栅栏（照 eprint/agent-bar，防 DNS rebinding 与跨站直连）：仅 GET；`sec-fetch-site ∈ {same-origin, none}`；Host 必须是 loopback 或 `ctx.webRuntime.trustedHosts` 允许的地址（骨架先做 sec-fetch-site + loopback 检查并留 trustedHosts 接入点，接线时从 eprint `index.js` 移植完整写法）。

## 6. 数据源方案（任务①）

### 6.1 三个候选

| 方案 | 说明 | 评价 |
|---|---|---|
| D1 构建时快照 | 安装包内带一份 data.json | ❌ 永远过期，只能当兜底/演示 |
| D2 定期由 airmon 生成 JSON | 给 airmon 加一步「另存脱敏 JSON」 | ❌ 违背禁改 `airmon/`/`run.py` 约束；且多一条调度链路要维护 |
| **D3 host 按需读取 + 过滤 + 缓存（推荐）** | 插件 host 每次收到 `/data` 请求时 stat `dashboard/index.html`，mtime 变了才重新「提取→过滤」，否则返回内存缓存 | ✅ 零调度、零改动、天然新鲜（打开面板才读）、单点过滤保证零机密 |

数据流与新鲜度：`auto_run.bat → run.py all → dashboard.generate()` 每 ~3h 重建 index.html；用户点开侧栏 → 桥请求 → host 读最新 → 响应。无需轮询；后续如需 badge 提醒，可在 client 加 5 分钟级 `setTimeout` 拉取（v2）。

`logic.js` 读取路径解析顺序：环境变量 `AIRMON_DASHBOARD`（显式指定 index.html 路径）→ 默认 `E:\Hermes-Agent\Jichang-Monitor\dashboard\index.html` → 都不可读时回退包内 `data.json` 快照并在响应里标 `_source: 'snapshot'`。响应始终附 `_source` 与 `_fetchedAt`，面板 footer 如实展示数据来源。

### 6.2 白名单过滤（零机密的关键，`sanitize()` 的精确契约）

**剔除**（原始 JSON 里的敏感/超范围字段）：
- `detail.nodes[].s`（节点服务器域名/IP）、`detail.nodes[].o`（端口）
- `info.panel`（机场面板地址）
- `detail.owners`（RDAP 归属，暴露托管基础设施）
- `detail.findings / detail.added / detail.removed`（原始证据与节点名列表，卡片不需要）
- `quota.source / quota.at`（快照指纹，非展示必需）
- `alerts[].hw`（华为证据原文，仅保留计数 `hw_n`）
- `single`（单机场视图，本面板不用）
- 兜底负向扫描：`ss:// vmess:// trojan:// hysteria2:// vless:// tuic:// token password secret uuid= http(s)://` 及已知节点域名/IP 逐个比对，命中即拒发。

**保留**：
- 顶层：`generated_at, base_local, quota_at, stale_hours`，`totals{airports,dirs,with_nodes,nodes,hits,zero_pull,stale,expiring30,expired}`，`runlog{start_local,done_local,duration_min,final_aps,final_nodes,ok_n,ok_nodes,ok_top,skipped,zero,auth,inflight,note}`，`hw_ledger{airport,rule,evidence,count,last_ts_local}`（华为命中区主特性；evidence 为 RDAP 公开组织名，无端点/凭据），`hw_current`
- 每机场：`slug, route, status, nodes, pull_zero, age_h, latest_ts, latest_local, snap24, added_n, removed_n, no_prev, hit_n, proto_top, expire, usage_pct` + 派生 `geo_top`（国家分布，由 `c` 字段聚合，**不含 s/o**）+ `quota{expire_date, days_left, total_gb, used_gb, used_pct, unlimited}`（若有）
- `alerts{ts, ts_local, airport, hw_n, added_n, removed_n}`

> 原型 `data.json`（54,442 B）即按此契约产出，负向扫描 CLEAN。插件 `logic.js` 的 `sanitize()` 与原型提取脚本同构，字段变更时只改这一处。

## 7. 插件文件结构清单（精确到字段）

骨架已完整落在 `docs/08-原型/plugin/`，逐文件说明：

```
plugin/
├─ package.json         # 见下方逐字段
├─ cordis.patch.yml     # 见下方逐字段
├─ index.js             # Host 壳：webServer prefix 路由 + 栅栏
├─ logic.js             # 读 index.html → 提取 → sanitize → mtime 缓存（热更目标）
├─ client.js            # __ModuleLoader__.load：slots 注册 + iframe + postMessage 桥
├─ panel.html           # 面板页 = docs/08-原型/airmon-panel.html 发布副本（桥模式优先，file:// 双击降级）
├─ data.json            # 构建时快照（兜底/演示，零机密）
├─ locale/en.json       # {"meta":{"title":"Airport Monitor","description":"..."},"panel.title":"Airport Monitor"}
├─ locale/zh.json       # {"meta":{"title":"机场监控","description":"..."},"panel.title":"机场监控"}
├─ icon.svg             # 单色描边图标，currentColor，≤256KiB，包内
└─ README.md            # 接线速查（与 §11 同步）
```

**package.json 逐字段**：
```json
{
  "name": "@local/airmon-sidebar",          // cordis 行 id 对应的提供者名
  "version": "0.1.0",
  "type": "module",                          // ESM
  "description": "机场监控侧边栏面板：KPI/47 机场卡片/套餐到期/告警流/华为命中",
  "icon": "./icon.svg",                      // 顶层 icon 字段（exports 亦含 ./icon）
  "exports": {
    ".": "./index.js",                       // Host 入口
    "./client": "./client.js",               // Web 客户端入口（dsh.client 段引用）
    "./icon": "./icon.svg",
    "./panel": "./panel.html",               // 声明式暴露（host 路由直接读文件，不依赖此 export）
    "./locale/*.json": "./locale/*.json",    // 显示元数据
    "./package.json": "./package.json"
  },
  "files": ["index.js","logic.js","client.js","panel.html","data.json","icon.svg","cordis.patch.yml","locale/"],
  "engines": { "dsh": "*" },                 // 版本豁免会阻塞安装，本地包用 *
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": {
      "platform": "web",
      "immediately": true,                   // 随 GUI 启动即载，不等用户触发
      "inject": [                            // 宿主 client 包（照 eprint/agent-bar 现行值）
        "@deepseek-ai/dsh-client-ui-slots",
        "@deepseek-ai/dsh-client-ui-sidebar",
        "@deepseek-ai/dsh-client-ui-layout",
        "@deepseek-ai/dsh-client-locale"
      ]
    }
  }
}
```

**cordis.patch.yml 逐字段**（bundle 自带，装包即注册，**无需改 profile 层**）：
```yaml
- insert:
    - id: airmon-sidebar          # cordis 行 id（面板与行的稳定标识）
      name: '@local/airmon-sidebar'  # 提供者包名，须与 package.json.name 一致
```
可选的 profile 级覆盖（禁用/调参时才加，加在 `C:\Users\minions\.dsh\profiles\desktop\cordis.patch.yml`）：
```yaml
- id: airmon-sidebar
  name: '@local/airmon-sidebar'
  disabled: false        # true=停用
  config: {}             # 未来加配置项时在此覆盖
```

**index.js 导出面**：`name` / `inject = ['webServer','webRuntime']` / `apply(ctx)`——`apply` 内 `ctx.webServer.register({ kind:'prefix', path:'/airmon-sidebar/api', handler })`，handler 见 §5。
**client.js 结构**：`window.__ModuleLoader__.load({ id:'@local/airmon-sidebar', factory(require){…} })`；factory **无副作用**，只 `require('react')` 并返回组件工厂；`inject:['slots','layout','locale']`；`apply(ctx)` 内完成两个 `ctx.slots.inject` 注册 + 全局 message 桥监听（`ctx.effect` 挂载、返回清理函数，HMR 安全）。
**slots 注册参数**（照 eprint 契约）：`{ name:'sidebar.panellist', id:'airmon', order:30, label:'机场监控' }` + 图标组件；`{ name:'main', key:'airmon', locale:'airmon-sidebar' }` + iframe 面板组件。`id` 与 `key` 同名是 sidebar 的映射约定，勿改。

## 10. 安全与脱敏声明

- **零机密**：`data.json` 与 `panel.html` 内嵌快照均按 §6.2 白名单产出，负向扫描（协议 URL、凭据关键字、已知节点域名/IP 清单）通过；节点服务器域名/IP、面板地址、owners 不进入任何交付物。
- **host 侧过滤是唯一出口**：原始 index.html 只在 host 进程内被读取，浏览器永远拿不到未过滤数据；C 路线（独立端口）因无法保证这一点被排除。
- **栅栏**：仅 GET + `sec-fetch-site` 同源校验 + loopback/trustedHosts Host 校验；沙箱 iframe（opaque origin）无 cookie/storage/直接 fetch 能力，数据只经 postMessage 桥。
- profile `cordis.patch.yml` 中的 apiKeyEnv 类条目与本插件无关，勿混写。
